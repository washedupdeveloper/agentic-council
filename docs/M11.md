# M11 — the rebuild: specification, amendments, evidence

M11 was written as a proposal in the v1 tree after M10 closed. This is the v2
copy: the targets as they were stated, every amendment the build forced, and the
command that decides each acceptance criterion. Where this page and the proposal
disagree, this page is the decision record — it does not pretend the proposal
said something else.

> Historical milestone record: the module, line and test counts below describe
> M11, not the current tree. `docs/FOUNDATIONS.md` states what the tool rests on
> today; `docs/M25.md`, `docs/M26.md` and `docs/M28.md` are the milestones after
> this one. See `HANDOFF.md` for the last verified state.

## What M11 is

Not a feature. A rebuild beside v1.9.0, which stays the reference binary until
the rewrite passes the same corpus. The product is one verdict derived from
evidence states — `pass`, `fail`, `incomplete` — where a finding is a claim until
a check settles it, and only a check that **holds** fails a run.

## Amendments

1. **Five proof kinds at M11, not seven.** `dom` was v1 scope creep — its golden runs
   never contained a DOM proof, and its selector grammar read unsupported
   selectors as "absent". `http` is SSRF-shaped, unsandboxed, and not evidence
   about a diff. Retrieval survives as a caller-supplied `--context-url`:
   bounded, digested, recorded, and never a proof. M25 later added `repro`;
   the current set is six.

2. **`council`, not `reviewc`.** One name for the package, the binary, the image
   and the skill.

3. **Verbs are `review`, `ci`, `init`.** `explain` was not built: `verdict.json`
   is the explanation, and a second renderer would be a second vocabulary. `ci`
   is the proposal's CI verb — `review` with the advice switches removed, always
   JSON, always the verdict as its exit code. `init` keeps `.council/` out of
   `git status`. The claims registry is a maintainer entry point, not a user
   verb: `council-verify`.

4. **22 one-owner modules replace the ≤ 6 target.** The count was a proxy for
   the disease: 35 modules, four duplicated file lists, 15 modules with an
   opinion about the threshold. The constraints that actually prevent that are
   the 4,000-line cap (2,121), one owner per rule (`git` is reachable in exactly
   one module, enforced by a test), and a purity gate over the decision path.
   Merging 22 coherent modules into six would recreate multi-reason modules.

5. **Three artifacts.** The wheel was added at the user's request and is the
   only artifact that needs no nix: `pip install council-<version>-py3-none-any.whl`
   on Python 3.11+, zero dependencies. The image ships the tool with bubblewrap.
   The flake builds both; it is never required on the user's machine.

6. **Exit codes are 0/1/2, and 3 is a start failure.** The proposal said 0/1.
   `incomplete` is a distinct outcome — missing evidence blocks a merge without
   claiming the change is bad — and a usage error must not reuse its code.

7. **There is no score, not even the optional integer.** The blocking set is the
   verdict. A number may be reported beside it as a trend; it cannot change it.
   Calibration was deleted with the number, because there was nothing left to
   calibrate.

8. **Context is part of the review.** The diff plus the enclosing function of
   every changed Python line, then the repository functions those call, two
   levels deep. Anything the resolver cannot follow is named, not dropped.

## Parity with v1.9.0

v1's six-rung corpus (`fixtures/corpus/claims-2026-11-05.json`) recorded three
clean rungs at 97.83, 97.83 and 100.00 (certified), and three rungs with a
seeded credential at 73.46, 76.83 and 73.46 (unsatisfied). v2 reviewed the same
six trees:

| rung | v1.9.0 | v2 |
|---|---|---|
| level-0, three runs | certified | **pass**, 0 findings |
| level-1, three runs | not certified | **fail**, 2 findings each |

`tools/corpus.py collect` reports **6/6 rungs correct**; the run is stored at
`fixtures/corpus/v2-results-2026-11-07.json`, produced 2026-11-07 with the
`council-generalist` profile.

The mapping is the only one that exists: v1's `certified` is v2's `pass`, and
v1's `unsatisfied` is v2's `fail`. v2 adds `incomplete`, for evidence it could
not obtain — a state v1 could not distinguish from a failure it never checked.
That is why `tools/differential.py` records the golden round as INCOMPLETE rather
than copying v1's verdict.

## Not done

- v1 is not maintained in this workflow. Its behavior is preserved by the
  fixtures and the differential check in this repository; no live v1 checkout
  is required.
- `v2.0.0` is tagged locally (M14); nothing is pushed, which remains the
  repository owner's action.
- The pinned toolchain is built on Linux only. This is unchanged from v1 and
  does not affect the wheel, which carries no toolchain.
