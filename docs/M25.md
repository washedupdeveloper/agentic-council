# M25 — Evidence that can fail

Three defects in the instrument were found by using it on a repository that is
not this one (`odysseus-dev/odysseus`, 169 findings, 18 verified by hand). Each
one is a case of a proof that could not fail for the reason the finding claimed.

## The defects

1. **A quotation "proved" a false finding.** The single high-severity security
   finding in the first round was proven by a `present` proof and was wrong on
   reading: the loopback check it described lives one layer up, in `app.py`. A
   quotation shows that a line exists; it cannot show that the code misbehaves.
2. **An absence over the whole repository refuted true claims.** `absent`
   searched everything, so an unrelated `lru_cache` in another file refuted two
   true claims about `turn_contract.py`, and a docs mention refuted a code-level
   claim.
3. **The digest hashed the instrument's name, not its configuration.** Switching
   a profile from one model to another changed every sample while `digest` stayed
   identical; two runs against different models were recorded as the same
   evidence.

## Decisions

1. **`repro` is a proof kind.** `{"argv": [...], "contains": "text"}` — the
   command runs and the finding is proven only when the command **fails** and its
   output contains the claimed failure. It is the only kind whose failure is the
   claim, and it shares the `command` executor's allowlist and sandbox.
2. **`absent` takes a scope.** `{"pattern": ..., "within": ["src/**"]}` restricts
   the search to the subtree the claim is about. A scope that matches no file is
   `UNRUNNABLE`, not proven: an absence proved over nothing is not an absence,
   the same rule as a review scope that removes every file.
3. **The digest covers the agent's configuration bytes.** `agents/hermes.profile_fingerprint`
   reads `$HERMES_HOME/profiles/<name>/config.yaml`, hashes it, and
   `instrument_digest` folds that hash and the adapter name into the digest. An
   unreadable profile is recorded as unknown (`profile_config: ""`), never assumed
   unchanged.
4. **A proof carries its kind into the verdict.** `ProofOutcome.kind` is set by
   `run_proof`, so a later reader can tell what settled a finding without
   re-parsing the params (this is what M28's `proof_strength` builds on).

## Rejected

- **Make `repro` mandatory for behavioural claims.** The tool cannot classify a
  claim as behavioural; a rule it cannot enforce is a rule the model will ignore.
  M28 records the strength instead and lets the caller decide.
- **Let `absent` keep searching everything and treat a hit as a coincidence.** A
  proof whose result depends on unrelated files is not a proof.
- **Hash the profile name only.** The name is a label; the model, the effort and
  the settings are what change the answer.

## Acceptance

| id | statement | command |
|---|---|---|
| 25.1 | a failing repro proves the finding | `pytest tests/test_proofs.py::test_a_repro_that_fails_proves_the_finding -q` |
| 25.2 | a succeeding repro refutes it | `pytest tests/test_proofs.py::test_a_repro_that_succeeds_refutes_the_finding -q` |
| 25.3 | a repro must show the claimed failure | `pytest tests/test_proofs.py::test_a_repro_must_show_the_claimed_failure -q` |
| 25.4 | a scoped absence ignores a hit outside the scope | `pytest tests/test_proofs.py::test_a_scoped_absence_ignores_a_hit_outside_the_scope -q` |
| 25.5 | an absence over nothing cannot prove | `pytest tests/test_proofs.py::test_a_scope_that_matches_no_file_cannot_prove_an_absence -q` |
| 25.6 | a changed model changes the fingerprint | `pytest tests/test_profile.py::test_a_changed_model_changes_the_fingerprint -q` |
| 25.7 | the digest follows the configuration | `pytest tests/test_run.py -k digest -q` |

## Known limits

- `repro` needs an allowlisted binary that can fail on demand. On a repository
  with no test runner it is `UNRUNNABLE`, and an `UNRUNNABLE` blocking finding
  makes the run `INCOMPLETE`.
- The fingerprint reads one profile's configuration. A reviewer that changes its
  model mid-run through the host's own configuration is not detected.
- `absent`'s scope is a glob list, not a semantic scope: `within = ["src/**"]`
  excludes a hit in `tests/` even when the claim is about both.
