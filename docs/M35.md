# M35 — Closing the residual breakpoints

This is the verdict record for `openspec/changes/close-milestone-residuals`.
M34 closed the verdict's silent failure paths. M35 closes the five places where
the system could still look complete while a guarantee was unproven.

## Rejected alternatives

- **Gate only the host system.** Cheaper, but `aarch64-linux` would remain a
  declaration without a run. Remove the system instead of pretending to gate it.
- **Trust the source tree in `doctor`.** A source run cannot prove what the
  installed binary contains; the version comparison is the cheap, honest check.
- **Keep `--samples 1` silent.** It is a deliberate reduction in evidence. The
  opt-in keeps the capability without the accident.
- **Rewrite profiles through a YAML round-trip.** It rewrites comments and
  ordering the selector does not own. The line patch is smaller and testable.
- **Hot-swap the council model from the report.** Surplus prices are spot and
  the profile is hashed into the instrument digest; the next run would use a
  different instrument. Profile emission is an owner action.
- **A `--yolo` runner with no shim.** The model could commit or change a
  profile. The shim is the boundary; the prompt is not.
- **A runner that requires a TTY approval for every write.** It would not be
  autonomous for reads, tests and workspace writes, which is the chosen
  boundary.
- **Automatic profile creation, commit or push.** Those are the owner's
  approval points; the runner prints the commands.

## What "autonomous" means here

The runner may read the change, write prompts and collab evidence, run tests and
write the workspace. It refuses `git commit`, `git push` and `hermes profile`
through a PATH shim, and it never invokes those commands itself. A task that
needs a profile change stops and prints the `hermes profile create` command.
The default worker uses `--yolo` because a one-shot has no TTY; the shim, not
the model, enforces the boundary. `--strict-approvals` omits `--yolo` for an
owner who wants to answer prompts in a TTY.

## Shell contract

`docs/SHELLS.md` records the invocation rule for fish and WSL: `wsl.exe --`
goes through the login shell, `wsl.exe --exec bash` does not; it also carries
the bash/fish/PowerShell translation table and states that a milestone
predicate runs under `/bin/sh`, not the caller's shell. The contract is
gated by `tests/test_shell_scripts.py` and the claim
`shell-scripts-declare-and-parse-as-bash`. The counts above are current, not
the close-time snapshot.

## Residuals

- The aarch64 gate is CI-only until an arm runner executes it; the local check
  reports the omission and makes no cross-system claim.
- The installed `council` binary is still a separate build; `doctor --source`
  detects a version mismatch, but the rebuild remains an owner action.
- The default runner uses `--yolo` under the shim. `--strict-approvals` is
  available, but a one-shot without a TTY cannot answer prompts.
- `routing.yaml` carries an optional `profile` per task; without it the runner
  uses `--profile`, default `council-generalist`.
- The task prompt is `tools/milestone-task.txt`; changing it is a repository
  change, not an OpenSpec artifact.
- No commit, push or profile creation is automatic, by design.
