# M33 — One reviewer seam, Hermes as the reference adapter

The request was to make the reviewer agent a replaceable component while keeping
the review engine, prompt, evidence and verdict unchanged. The CLI and the
editor/protocol servers already expose the same `council` command; the missing
piece was a named adapter boundary instead of a Hermes-shaped function in the
transport.

## Decision

`src/council/agents/` is the seam:

- `base.py` owns `AgentOptions`, `AgentIdentity` and the `AgentAdapter` protocol.
- `hermes.py` owns the Hermes CLI argv, profile fingerprint, stream reader
  configuration and executable check.
- `__init__.py` owns the explicit `BUILTIN` table and the name registry.

The review engine calls `resolve(name).runner(options)`. It never imports an
agent SDK, never parses an agent's configuration and never knows a command line.
The `--agent` option is available on `review`, `ci`, `pr` and `doctor`;
`council agents` lists what the build carries.

Only Hermes is registered. A second adapter is a module plus a `BUILTIN` entry,
documented in [`AGENT-ADAPTERS.md`](AGENT-ADAPTERS.md). A generic "run any
command" adapter is deliberately not shipped: prompt delivery, output shape and
read-only policy are adapter-specific and need verification against the real
agent.

The run records both the generic facts (`agent`, `reviewer`, `agent_config`,
`agent_config_sha256`) and the Hermes profile fields kept for existing verdict
consumers. The instrument digest includes the agent name and the adapter's
identity hash.

## Rejected

- **Keep `hermes_runner` as the public seam.** A binary override would still send
  Hermes flags to a non-Hermes CLI; it is not an adapter.
- **Discover arbitrary Python modules at runtime.** An unreviewed transport is a
  code-execution path. The built-in table is explicit; embedding tests can
  register a test adapter in-process.
- **Ship a generic command adapter now.** It would move the hard decisions
  (stdin/file, output format, read-only, identity) into user configuration
  without a tested example. The extension document states the contract instead.
- **Put the adapter registry in the ACP/MCP servers.** They remain process
  boundaries around the public CLI; adding agent logic there would create a
  second integration path.

## Known limits

- Only Hermes ships; every other adapter needs a real command test.
- A host editor's own skills and model are not passed to the reviewer; the
  reviewer's agent configuration is server-side.
- A panel of several agents at once is not implemented. This milestone selects
  one adapter per run; ensemble semantics need their own merge and provenance
  decision.
- The `--profile`, `--reasoning` and stream switches are currently Hermes
  options. Future adapters may ignore them or reject them explicitly.

## Verification

The normal V2 gate is authoritative: pytest, mypy, pyright, ruff F/E9,
`council-verify`, mutation checks and `nix flake check`. The adapter tests use a
test-only second adapter through the same `review` path; the built-in Hermes
adapter continues to use the real CLI in the existing transport tests.
