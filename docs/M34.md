# M34 — Closing the review breakpoints

This is the verdict record for `openspec/changes/close-review-breakpoints`.
The change is the contract; this page is the short engineering account of what
the remaining breakpoints were, what was traded away, and what the gate now
proves.

## Breakpoints and verdicts

| Breakpoint | Before | After | Trade-off | Verdict |
|---|---|---|---|---|
| Distinct claims at one line | Key `(file, line)` collapsed them | Key `(file, line, normalized claim)` keeps both; case/whitespace still merge | Paraphrases now produce separate rows | Adopt; completeness beats tidy row count |
| Clean auto-sampling | One clean sample was enough | Two clean samples; a finding on the second asks a third | One extra sample on a clean unit | Adopt; absence needs confirmation |
| Strict proof mode | Quotation-only blocker could leave a PASS | Quotation-only blocker is INCOMPLETE | More INCOMPLETE results | Adopt; no false green |
| Malformed reviewer output | Unknown dimensions could be dropped; no proof became REFUTED | Unknown dimension is a schema failure; no proof is UNSETTLED | More failed samples / incomplete runs | Adopt; fail at the boundary |
| Merged wording | Merge held all wordings; the verdict kept only the first | `Finding.claims`; `verdict.json` carries every wording | Slightly larger verdict | Adopt; additive |

| Dev-only verifier shipped | `council-verify` installed in the Nix app with no pytest, so every claim failed outside the devshell | The Nix runtime app ships only `council`; the devshell entry point is `nix develop -c ./bin/council-verify` | Nix runtime users lose a broken convenience command; pip keeps the developer entry point | Adopt; no misleading tool |

## Rejected alternatives

- **Semantic merge by similar wording.** Requires a model and makes the report
  non-deterministic. Exact case/whitespace normalization is the only merge that
  can be replayed.
- **Always three samples.** Stronger clean evidence, but a fixed cost increase
  for every clean unit. Two clean samples is the smallest confirmation; a caller
  who wants more asks for `--samples 3`.
- **Pass when strict mode discards a quotation.** That is the false-green path
  this record exists to remove. A quotation can show text; it cannot settle a
  behavioural claim.
- **A heuristic anomaly detector.** An explicit schema failure is testable and
  explainable; a heuristic is neither.
- **A reviewer panel.** Prior measurement: one generalist sampled N times caught
  22/22 injected defects; five isolated specialists caught 13/22 at equal cost.
  Diversity remains two independent council runs.

## What "zero failure points" means here

It does not mean no process can fail. It means **no silent failure path**:

- missing reviewer → start failure, exit 3;
- malformed or unknown output → failed sample, run INCOMPLETE;
- no attempted proof → UNSETTLED, blocking run INCOMPLETE;
- static-only blocker under strict mode → INCOMPLETE;
- proven executed blocker → FAIL;
- only a complete, non-blocking evidence set → PASS.

The remaining non-code limits are explicit: the installed `council` binary can
be older than the source tree and must be rebuilt before using the `direct`
adapter; `council-verify` is not installed by the Nix runtime app and must be
run as `nix develop -c ./bin/council-verify` from the source tree; and a
host-only `nix flake check` makes no cross-system claim.
