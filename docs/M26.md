# M26 — The third rung: line windows

M12 sliced a change by file, then by hunk, and refused below that. That ladder
has a floor with no rung: an **added file is a single hunk carrying every line**,
so the two slices are the same text. `src/agent_loop.py` in the odysseus audit is
38,416 lines in one hunk — a 1,840,424-byte prompt against a 32,768-byte limit,
and no `--max-prompt-bytes` value makes that a prompt a model can answer.

Before this milestone the tool said, correctly and uselessly: *"narrow the change
with `--base`"* — to a user whose change was one file.

## Decisions

1. **A hunk too large for the budget is split into line windows, off by default.**
   `--window-large-files` splits it; without the flag the refusal stands. Windows
   are byte-greedy (`planning.window_bounds`, prefix sums over the hunk's body),
   so a window's boundary is a fact about this prompt rather than a line count.
2. **A window is a valid diff, not a slice of text.** `changes.Hunk.slice`
   re-emits the `@@ … @@` header by walking the counters over the lines before
   the window, so `change_lines` reads the same added and removed numbers from a
   window as from the whole hunk. A window that renumbered its lines would break
   every `diff` proof that cites them.
3. **The refusal states the cost.** `PromptTooLarge` carries the window count and
   the samples it implies (`N`, or `N`–`3N` with confirmation), because the
   choice being offered is expensive in wall-clock, not in bytes. The interactive
   prompt offers `window` as an answer and prints the same count first.
4. **A ceiling, `--max-windows` (default 200).** Past it the change is refused
   even with the flag: a thousand samples is a crawl, not a review.
5. **Windows are reviewed at context depth 0.** Context around a fragment makes
   the prompt larger for no gain — on a file that needs windows the enclosing
   function is already past the context builder's 400-line span limit — and depth
   0 is what makes the byte accounting exact.
6. **The accounting has one owner.** `planning.prompt_overhead` is the only place
   that knows what a prompt spends before the diff (template, rules, references).
   A window sized from anything else is a window that does not fit.

## Rejected

- **Raise the default budget.** 1.84 MB is ~460k tokens; the limit is not the
  binding constraint, the model's context is.
- **`--allow-large-prompt`.** It sends the prompt whole (`sliced = false`), which
  turns a refusal into a hang.
- **Drop the file and review the rest.** Unrecorded exclusion is the failure mode
  the scope machinery exists to prevent.
- **Overlapping windows.** They double-count findings at a boundary and break
  "every unit is disjoint". The cost is accepted and documented instead.

## Known limits

- **A defect that spans a window boundary is missed.** Windows are disjoint.
- **A window is a fragment.** The reviewer sees a line range of one file with no
  cross-file context; a claim that needs the whole file is not reachable.
- **The cost is wall-clock, not bytes.** 62 windows at one sample each is a
  different kind of decision from 6, and the refusal says so rather than deciding
  for the caller.
- **Windowing does not help a budget below the template.** At a limit smaller than
  the reviewer prompt itself, no window can fit and the refusal carries no
  window count — which is the honest answer, and was observed at 1,500 and 2,500
  bytes.
