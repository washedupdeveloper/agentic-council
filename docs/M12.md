# M12 — review any change

M11 gave the tool a verdict derived from evidence, a budget, and a refusal that a
person can answer. It has one measured limit: a prompt above the budget is not
reviewed. The feature commit itself is 24 KB of diff and only fits at context
depth 0 (31,478 bytes against 32,768); a larger change gets refused, and the
provider does not answer a 60 KB prompt at all.

M12 removes that limit without weakening the verdict: a change too large for one
prompt is **sliced** into units that fit, each unit is reviewed, the findings are
merged, and the coverage is recorded. A unit that could not be reviewed makes the
run **INCOMPLETE** — never a pass.

## Decisions

1. **Unit shape: file first.** A file is reviewed whole when its prompt fits. A
   file that does not fit is split by hunk; each hunk carries the file's diff
   header, so the reviewer still sees the path and the change.
2. **Slicing is automatic.** When the whole prompt exceeds the budget, the run
   slices instead of refusing. There is no `--slice` flag: the tool does the
   obvious thing, and the refusal remains for a unit that cannot fit at all.
3. **Samples are per unit.** Each unit gets the same sampling rule as a whole
   review: one clean sample, a second to confirm a finding, a third to break a
   tie. An explicit `--samples N` means N samples per unit.
4. **A unit that still exceeds the budget at context depth 0 asks the person**,
   exactly as an oversized whole prompt does today (`allow`, `budget N`,
   `base REV`, `context N`, `?`, `cancel`). With no terminal, or with
   `--autonomous`, it refuses and no reviewer is called.

## Shape

```
one review
  whole prompt fits?  ── yes ──▶ one unit (today's path)
        │ no
        ▼
  file sections, in patch order
    file prompt fits? ── yes ──▶ unit: the file
        │ no
        ▼
    hunks of that file, in order
      hunk prompt fits? ── yes ──▶ unit: one hunk, with the file header
        │ no (depth 0)
        ▼
      PromptTooLarge(unit) ──▶ ask a person, or refuse
```

A unit's prompt is the reviewer template, that unit's diff, and the context at
the **deepest depth that fits** (the requested depth first, then lower; the depth
used is recorded per unit). References supplied with `--context-url` are included
in every unit.

## Coverage and verdict

- Findings from every unit are merged by `(dimension, file, line)`: the highest
  severity wins and every proof is kept.
- The global verdict is `judge` over the merged findings, with one addition: if
  any unit's samples did not all answer and the verdict would be `PASS`, it is
  `INCOMPLETE`, naming the units.
- `verdict.json` gains `sliced` and `units[]`: each unit's id, files, line
  ranges, diff digest, prompt bytes, context depth, samples, findings count and
  its own verdict (`pass` / `fail` / `incomplete`).
- Sample files live at `.council/runs/<id>/units/<unit-id>/sample-N.json`.

## Acceptance

| # | criterion | what decides it |
|---|---|---|
| M12.1 | a change whose whole prompt exceeds the budget is sliced automatically | a two-file fixture with a tiny budget yields two units and a verdict, no refusal |
| M12.2 | a file too large is split by hunk, header preserved | a one-file fixture with a tiny budget yields hunk units, each naming the file |
| M12.3 | findings merge across units | the same place reported by two units appears once, highest severity, all proofs |
| M12.4 | an unreviewed unit forbids PASS | a unit whose reviewer fails makes the run INCOMPLETE and names the unit |
| M12.5 | a unit that cannot fit at depth 0 asks | `PromptTooLarge` carries the unit; interactive dialogue answers it; non-interactive refuses |
| M12.6 | the gate stays green | `nix flake check`, claims, mutations, release check |
