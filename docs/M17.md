# M17 — Pull-request entry and a plan

Two doors into the same review: one for a GitHub pull request, and one for
seeing what a review will cost before it is paid.

## Scope

1. **`council pr NUMBER`** — `gh pr view` supplies the PR's base and head SHAs;
   the command verifies the checkout is exactly that head commit with a clean
   worktree, then reviews `base..HEAD` through the ordinary pipeline. It never
   checks a branch out and never reviews local edits. `verdict.json` records the
   PR's number, URL, title and both SHAs.
2. **`council review --plan`** — resolves the change, builds the context and
   prompt, and prints the units (files, ranges, prompt bytes, context depth) and
   skipped files. It calls no reviewer and writes no run directory. `--json`
   returns the same as objects. `council pr N --plan` works for a PR.

## Decisions

- **A PR review is a commit review.** The tool refuses to review a dirty
  worktree and refuses a checkout at another commit; it tells the user the
  `gh pr checkout` command instead of switching branches for them.
- **The base belongs to GitHub.** `pr` has no `--base`; overriding it would
  review something that is not the pull request. The interactive oversize
  dialogue omits the `base` choice for the same reason.
- **A plan is a preview, not a run.** It may fetch caller-supplied
  `--context-url` references because they change the prompt size, but it writes
  no run directory and asks no reviewer. If a unit cannot fit at depth 0 it
  reports the refusal (exit 3) instead of pretending a plan exists.
- **Plan and review share `_prepare`.** The prompt-building path has one owner,
  so the bytes a plan prints are the bytes a review would send.
