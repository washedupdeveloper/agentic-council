# M19 — Ephemeral by default

M18 made the reviewer sandboxed and gave the run an opt-in ephemeral mode. M19
makes ephemerality the default and states what a host without NixOS can do.

## Scope

1. **Ephemeral by default.** `review`, `ci` and `pr` create the run in a private
   temporary tree and remove it after the verdict. `--no-ephemeral` writes
   `.council/runs`; `--keep DIR` copies the run before removal. The verdict is
   printed and SARIF written before the tree is removed; a failed run removes
   its tree too.
2. **Ephemeral command wrapper.** `tools/sandbox.sh -- <command>` runs any
   command with a read-only root, a private `/tmp` and an overlay `$HOME` on
   Linux/bwrap. Writes to `$HOME` and `/tmp` vanish with the process; it refuses
   with exit 3 when bwrap is absent instead of degrading silently.
3. **Portability.** `docs/PORTABILITY.md` states the matrix: NixOS and Linux use
   bwrap; macOS, Windows and any OCI host use the container as the boundary;
   native Windows uses WSL2. A plain `Dockerfile` builds the tool without Nix.
4. **Honesty.** Where no boundary exists, `reviewer_sandbox: false` is recorded;
   `--ephemeral` still removes the run tree, but it does not claim to sandbox a
   process it cannot.

## Acceptance

| 19.3 | the command wrapper's writes to `$HOME` and `/tmp` do not reach the host | `python -m pytest tests/test_sandbox_script.py` |

## Live evidence

- `tools/sandbox.sh -- bash -c 'touch $HOME/…; touch /tmp/…'` ran inside the
  sandbox and both host markers were absent; `id -u` was `1000`.
- With `PATH=/usr/bin:/bin` (no bwrap) the same wrapper printed the install
  hint and exited **3**.
- `Dockerfile` is a source recipe; it is **not built in this environment**
  (no Docker/Podman daemon here). The canonical image is `nix build .#image`.

## Decisions

- **Ephemeral is the default because the verdict is the product.** A run
  directory is kept only when `--keep` asks for it; `.council/runs` is the
  explicit legacy form.
- **The wrapper is Linux/bwrap only.** On macOS and Windows the container is the
  boundary; a shell script that silently falls back to a temp `$HOME` would be a
  weaker sandbox wearing the same name.
- **No network isolation.** The reviewer needs the model; bwrap and the
  container keep the filesystem boundary, not the network one.
- **The Dockerfile is honest about its status.** It is the non-Nix source path;
  it is not claimed as tested until a Docker/Podman host builds it.
