# M36 — Closing the Astra review findings

This is the record for `openspec/changes/fix-council-review-findings`. The
council ran against Phoenix, agentic-council and hermes-skills; this milestone
closes the findings that were inside the council's own release boundary.

## Fixed

|---|---|---|

corners, every one with a regression test:

| Defect | Fix | Regression proof |
|---|---|---|

| Defect | Fix | Regression proof |
|---|---|---|

Two further passes closed the remaining containment and fidelity gaps:

| Defect | Fix | Regression proof |
|---|---|---|
| The sandbox masked only `/home` and `/root` | The caller passes every masked tree, including a `$HOME` outside them | `test_a_repository_under_any_masked_directory_is_bound_back` |
| A directory replaced a lower-layer FIFO badly | A non-directory is cleared before the directory is created | `test_a_directory_replaces_a_fifo` |
| A `.` directory header, as `tar -cf x.tar .` writes, was refused | The root itself is permitted for a directory member and refused for any other | `test_a_dot_directory_header_is_accepted`, `test_a_member_naming_the_root_is_refused` |
| A root opaque whiteout failed instead of clearing the root | The root resolves and the entries beneath it are removed | `test_a_root_opaque_whiteout_clears_the_lower_layer` |
| An opaque whiteout kept cached links beneath it | The cache is cleared for the subtree, including keys resolved through an alias | `test_an_opaque_whiteout_forgets_links_beneath_it` |
| A module-specification error was read as a missing dependency | Only "No module named" is a dependency signal | `test_a_module_bug_is_not_a_missing_dependency` |
| A symlinked launcher looked for its helper beside the link | Both wrappers resolve their own symlink first | `test_the_launcher_finds_its_helper_through_a_symlink` |
| A read-only directory was chmodded before its children | Directory modes are applied after extraction, deepest first | `test_a_read_only_directory_can_still_be_populated` |
| Regular files lost their archived mtime | The member's mtime is restored after the write | `test_a_regular_file_keeps_its_archived_mtime` |
| Invalidation scanned every cached link per file | Invalidation is O(1) on the written path | covered by the cache tests |

A final group of passes removed the image materialiser's symlink cache
entirely. Every remaining finding in that file was cache invalidation — a link
replaced by a directory, a whiteout, a loop — so the cache was deleted and
resolution now walks the rootfs on disk, as a chroot does. That removed the
whole class rather than one instance of it. The same passes closed the proof
engine's remaining ambiguity (a `contains` match anywhere in the output was
accepted as evidence even when the run had died on a missing import; now the
match must name the diagnostic itself), and a deferred directory mode is applied
through a descriptor walked from the root, so a replaced ancestor cannot redirect
it outside the image.

## Targeted Astra passes

Astra reviewed the change fourteen times in this milestone. The first pass
found a real parser
regression and a rules guard that took its protected documents from the working
tree. Later passes found a critical traversal in the image materialiser's
parent-only check, a staged rule read that followed a symlink, and several
materialiser edge cases. Every critical and high finding was fixed and covered
by a regression test before the next pass.

A final pass closed the medium and low tail as well: the image path resolver
now follows the image's own symlinks (so a later layer can add a file beneath an
absolute link) without ever consulting the host, whiteouts act on the link
rather than its target, directory modes keep the sticky bit, a member name with
a parent segment is refused, and the milestone parser decodes YAML escapes.
Skipped paths count toward the rule guard, and a repro whose `contains` matches
its claimed import failure is evidence rather than an unrunnable proof.
