# M20 — Error-driven CLI hardening

A bad request fails before the expensive part. This milestone audited every
flag, path, base, config and proof parameter the CLI accepts, then made the
failure a named message and exit 3 instead of a traceback.

## Scope

1. **Preflight.** `review`, `ci` and `pr` validate the run id, profile, base,
   context URLs, prompt, reviewer binary, `--sarif` and `--keep` before a run
   directory or a model call. `--plan` runs the same checks; it refuses
   `--sarif`, `--keep` and `--report` because it writes no run.
2. **Start failures.** A missing reviewer is `ReviewerMissing` (exit 3), not a
   retried sample and not `INCOMPLETE`. An empty change, an unknown base, a
   malformed `council.toml`, a missing/non-UTF-8/FIFO prompt and an unwritable
   output path are start failures too.
3. **Path safety.** Run ids are one portable segment (no separators, `.`/`..`,
   control characters, Windows-reserved characters, surrogates, or >128 chars).
   `.council` and `.council/runs` must be directories, not symlinks. `--sarif`
   and `--keep` refuse symlinks, FIFOs and devices; `--keep` refuses a path
   inside the run directory. Untracked symlinks are named and skipped, never
   followed.
4. **Proof robustness.** A proof with a NUL, an unreadable tree, a non-regular
   file or an unexpected exception is `UNRUNNABLE`, never a crashed run. The
   `absent` walk does not follow symlinks.
5. **Output safety.** Human output strips Cc/Cf/Cs/Zl/Zp characters from model
   output and paths, so a finding cannot emit ANSI escapes or bidi controls.
6. **Exact numbers.** `--time-budget 0` means no budget and is accepted; a
   negative budget is a usage error. Usage errors remain exit 3 (2 is
   `INCOMPLETE`).

## Live evidence

The probes ran the real CLI against a temporary repository and a stub reviewer.
They covered: no args, `--version`, help, missing values, every numeric boundary,
invalid choices, run-id traversal/absolute/colon/control/129-char, prompt
missing/dir/FIFO/non-UTF-8/no-placeholder, SARIF/keep missing-parent/dir/FIFO/
device/symlink, empty base/profile/context, bad context URLs (including
`file://` dir/FIFO and a refused TCP port), missing/non-executable/dir/NUL
reviewer, repository missing/file/bare/.git/subdirectory/symlink, malformed/
directory/non-UTF-8/broken-symlink/FIFO config, `pr` 0/-1/abc/`--base`, gh
missing/invalid/failing, wrong head, dirty worktree, `--plan` conflicts, and
last-flag-wins combinations.

Result: every invalid request that reached the review, plan, PR or init path
exited **3** with a `council:` message; `council doctor` reports a failed check
as exit **1** by design. No traceback was produced. Valid invocations exited
0/1/2 as their verdict required. The bad run id case did not call `gh` at all.
No `.council` directory was left in the temporary repository.

## Decisions

- **Exit 3 for every start failure.** It is the only code that means "nothing
  was reviewed". Reusing 2 would confuse a missing reviewer with an incomplete
  review.
- **Refuse rather than silently ignore.** `--plan` with `--sarif` would look like
  a request to produce a log and produce nothing; an empty `--keep` would copy
  into the current directory; `--keep` inside the run directory would recurse.
  Each is an error.
- **Name and skip a symlink, never follow it.** A symlink in an untracked change
  can point at a secret outside the checkout; reading it into the prompt would
  be a data leak.
- **A proof crash is evidence that did not arrive.** `UNRUNNABLE` is honest and
  keeps the verdict `INCOMPLETE`; a traceback is not a review.
- **Sanitize only the human output.** `verdict.json` and SARIF keep the exact
  strings; the terminal gets a printable projection.

## Known limits

- `--sarif /dev/null` is refused because it is not a regular file. A user who
  wants to discard the log should omit `--sarif`.
- `--context-url` is fetched with a 30 s timeout; a black-holed host still costs
  that wait. The fetch is caller-supplied and never a proof.
- `council doctor` measures with `--probe-timeout`; a very small value reports a
  timeout rather than a broken profile.
- The `--repo ""` rejection is deliberate: an empty path is a typo, not ".". The
  default is the current directory when the flag is omitted.
