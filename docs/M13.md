# M13 — Bounded runs

A review must end by a time a person chose, even when the instrument does not
answer. This milestone adds the deadline and the measurement that makes a run
predictable on a slow or flaky provider.

## The problem

Each sample could wait out its full timeout and be retried once; a sliced change
multiplies that by the number of units. Measured on 2026-11-09: an 18-unit
review stalled twice for more than six minutes before any verdict, and the run
was stopped by hand. `--sample-timeout` bounds one attempt; nothing bounded the
run.

## What M13 adds

1. **`--time-budget N`** — after N seconds the run stops starting units. A unit
   never started is recorded with `samples_run: 0`, `ok: false` and
   `error: "time budget exhausted"`. The unit in flight is allowed to finish:
   the budget stops new work, it does not cut a sample in half. The verdict
   cannot be `PASS`; it is `INCOMPLETE` unless a proven blocking finding has
   already made it `FAIL`.
2. **`council doctor`** — measures what a review needs on this machine: `git`,
   the reviewer binary, `bwrap`, and whether the profile answers a one-line
   probe within `--probe-timeout`. `fail` exits 1; `warn` (no `bwrap`) exits 0
   and names the consequence (`command` proofs are `UNRUNNABLE`).
3. **`--sample-timeout N`** (landed in `eb3944b`) — one attempt cannot outlast
   the caller's patience.

## Decisions

- **Seconds, not units.** Machine speed varies; a unit count does not bound wall
  time, and the budget exists to bound wall time.
- **The unit in flight finishes.** Cutting a sample mid-prompt would produce
  half an answer and a failure that says nothing about the change.
- **A skipped unit is unreviewed, never clean.** `INCOMPLETE` is the only honest
  verdict when a unit was never asked, exactly as for a sample that returned
  nothing.
- **Doctor's warning is not a failure.** `bwrap` absent degrades `command`
  proofs to `UNRUNNABLE` — a recorded state with its own verdict — so the
  machine can still review files whose findings use `present`, `diff` or
  `schema` proofs.
- **The budget is recorded in `verdict.json`** (`time_budget`), so a run's
  evidence says which deadline produced the units it has.
