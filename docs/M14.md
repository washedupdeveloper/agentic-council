# M14 — Release and adopt

The code that exists must be installable, runnable where a user actually is,
and proven on a repository that is not this one.

## Scope

1. **Version 2.0.0.** The public surface changed from v1 (verdict from evidence
   instead of a score, `review`/`ci`/`init`, a wheel); 2.0.0 is the honest
   major version, not a 0.x label on a finished surface.
2. **The wheel** — built by nix, installed into a clean virtual environment,
   run end to end there with a stub reviewer, and shown to carry the prompt.
3. **The image** — built by nix, materialised and run: the artifact that
   carries `bwrap` so command proofs work where the host has no nix.
4. **The CI entry** — a composite action and a workflow that run
   `council doctor` then `council ci` with a sample timeout and a time budget.
   It is for a runner that has Hermes; the action never installs one.
5. **Adoption** — a bounded review of a real, external repository, recorded
   under `.council/runs/`.

## Decisions

- **The version is written once.** `pyproject.toml` is the source; flake.nix
  reads it for the package, the image tag and the wheel check; `council.__version__`
  reads the installed metadata and says `0.0.0+source` in a checkout.
- **The wheel is the no-nix artifact; the image is the no-install artifact.**
  The wheel cannot carry `bwrap`; the image does, and both are built by the same
  package definition.
- **The action does not install Hermes.** A reviewer is a host capability; the
  action checks for it with `council doctor` and fails early if it is absent.
- **A bounded adoption is still adoption.** The external run may return
  `INCOMPLETE` when the provider does not answer; the evidence is the run
  directory, not a green badge.
- **A local tag, no push.** `v2.0.0` is created here; publishing is the
  repository owner's action, not the tool's.
