# M15 — Transport guard

A reviewer that goes silent must cost the idle timeout, not the whole sample
timeout. This milestone makes the transport observable and gives it a watchdog.

## The problem

A non-streaming call is invisible until it finishes. When the provider stalled,
the runner waited out the full sample timeout and retried, so one dead request
could cost 30 minutes. The same prompt later answered, so the stall is the
provider's, not the prompt's.

## What M15 adds

1. **Streaming by default.** `--stream` reads `--format stream-json` events and
   takes the final `result.text` (or the concatenated `text` events) as the
   answer. `--no-stream` keeps the old one-shot call for a host whose Hermes has
   no `stream-json`.
2. **An idle watchdog.** With `--idle-timeout N` (default 120 s), a stream with
   no event for N seconds is killed and reported as
   “stream went silent for Ns”; the sample then retries once, exactly as for any
   other failed sample.
3. **The transport is recorded.** `verdict.json` gains `transport`
   (`stream`/`plain`) and `idle_timeout`, so a verdict says how it was obtained.
4. **No answer is an error.** A stream that ends without a `result` and without
   text, or whose `result` carries a non-zero exit, is `OSError` and retries; it
   can never become a pass.

## Decisions

- **120 seconds of silence.** The ultra stream showed a 62-second gap between
  `system` and its first `text` event while the model was thinking, so the
  watchdog must allow that. 120 leaves headroom and still cuts a dead request in
  two minutes instead of the sample timeout.
- **The watchdog kills; the sample layer retries.** There is one retry, as
  before; a second silence makes the sample fail, so the run is `INCOMPLETE` —
  never a pass.
- **Transport is not part of the instrument digest.** It changes how the answer
  is carried, not what the prompt means; the verdict records it, and the digest
  stays comparable across transports.
- **Streaming is the default because it is observable.** A non-streaming call
  cannot distinguish “thinking” from “gone”; the stream can, and the watchdog
  acts on that difference.
- **Kill the process group, not the process.** A wrapper's child can inherit
  the pipe; killing the parent alone leaves the reader waiting forever. The
  reviewer is started in its own session on POSIX and the group is killed, with
  a regression test for the child-holding-the-pipe case.
- **A retry does not erase the failure.** `sample-N.json` keeps every failed
  attempt in `failures`, so evidence of a watchdog kill is not inferred from the
  attempt count.
