# M31 — A pull request target may be a number, URL or branch

`council pr` accepted only a positive integer. GitHub already resolves a pull
request number, URL and branch to the same pull request, and an operator
usually has the URL in hand. Refusing the URL made the tool ask for a
translation GitHub had already done.

## Decision

The positional argument is now a target string. `pr._target` accepts a positive
integer or a non-empty, non-option-like target such as a URL or branch, trims
surrounding whitespace, and passes the value unchanged to `gh pr view`; an empty
or option-like value is refused before `gh` is called. The returned `number`,
`url`, `title`, base SHA and head SHA are what the review uses. The existing
checkout checks are unchanged: the worktree must be clean and HEAD must equal the
PR head.

Rejected:

- **Parsing the URL ourselves.** GitHub owns URL forms, redirects and host
  aliases; a local parser would reimplement them and could disagree with `gh`.
- **Converting a URL to a number first.** That adds a lookup with no new
  evidence and turns one `gh` call into two.
- **Accepting only a URL.** A branch is the form a person has after
  `git switch`; `gh pr view` resolves it with the same call.

Known limit: a branch with no open pull request is a `gh` failure and therefore
a start failure. Cross-host PR support is deliberately not part of this
milestone; `docs/FEATURES.md` records it as deferred.

## Acceptance

| id | statement | command |
|---|---|---|
| 31.1 | a URL is passed to `gh pr view` and resolves the PR | `pytest tests/test_pr.py::test_resolve_accepts_a_pull_request_url -q` |
| 31.2 | a branch is passed to `gh pr view` and resolves the PR | `pytest tests/test_pr.py::test_resolve_accepts_a_pull_request_branch -q` |
| 31.3 | an empty or option-like target is refused | `pytest tests/test_pr.py::test_an_empty_pull_request_target_is_refused tests/test_pr.py::test_an_option_like_target_is_refused -q` |
| 31.4 | both target claims are in the registry and their falsifiers are real mutations | `python3 tools/mutation_check.py` |
| 31.5 | every claim, including both target claims, holds | `./bin/council-verify` |
| 31.6 | the CLI hands the URL target to the resolver | `pytest tests/test_cli.py::test_pr_passes_its_target_to_the_resolver -q` |

The claim is `a-pr-target-may-be-a-number-url-or-branch`, with falsifier
`pr-target-is-ignored`, which replaces the resolved target with `"7"` before the
`gh` call. A second claim, `the-cli-passes-a-pr-target-to-the-resolver`, has
falsifier `pr-cli-target-is-ignored`, which passes `7` instead of the CLI's
target. The URL and branch tests assert the exact argv, and the CLI test asserts
the target reaches the resolver, so both mutations are caught and both claims
name a real falsifier.
